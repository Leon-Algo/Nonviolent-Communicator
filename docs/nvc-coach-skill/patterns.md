# NVC 教练技法（可执行模式）

## Pattern: OFNR 诊断
**When to use**：用户给出任意一句表达，想知道问题在哪。
**How**：逐要素判定——
1. 观察：有无具体时间/情境？有没有绝对化词（总是/从来/根本）？
2. 感受：是真实情绪词，还是"觉得/认为/感觉像"引导的想法？
3. 需要：说的是通用需要，还是某个具体人应该做的策略？
4. 请求：是当下具体、正向、可行的行动邀请，还是命令/模糊要求？
**Trade-offs**：诊断要一次只说 1-2 个最关键问题，不要四条全倒出来。

## Pattern: 评判 → 需要 翻译
**When to use**：出现道德评判、比较、讽刺、指责。
**How**：把"你 X（评判）"改写成"我感到…因为我需要…"。
- "你们总拖延不专业" → "我观察到两次里程碑延期（观察），我感到焦虑（感受），因为我需要可预测的节奏（需要）。"
**Trade-offs**：保留用户的真实意图，不要美化成完全相反的意思。

## Pattern: 猜测式同理回应
**When to use**：对方表达了强烈情绪，需要先被听见。
**How**：用疑问句给出猜测——"听起来你感到〈感受〉，因为你需要〈需要〉，是吗？"留出让对方修正的空间。
**Trade-offs**：猜测错了要允许被纠正，不要坚持自己的解读。

## Pattern: 三层停顿（自我同理）
**When to use**：用户说"我很生气/我忍不住想骂他"。
**How**：1) 停下来不反应；2) 识别脑中评判想法；3) 连接那个想法背后的需要。
**Trade-offs**：不要跳过第 2 步直接找需要——评判是通往需要的入口。

## Pattern: 愤怒四步
**When to use**：用户处于愤怒中。
**How**：停 → 认出评判想法 → 连接未满足需要 → 需要被看见后再表达。
**Trade-offs**：宣泄不等于处理；不要在愤怒峰值要求用户做 NVC 表达。

## Pattern: 请求具体化
**When to use**：请求模糊（"改一下""注意一下"）或带命令。
**How**：加上时间、动作、可验证标准，改为疑问句："你愿意在 X 时间前做 Y 吗？"
**Trade-offs**：请求必须允许对方说不；不允许就是命令。

## Pattern: 感谢三步
**When to use**：表达感激、复盘正向体验。
**How**：具体行为 → 我的感受 → 被满足的需要。三要素缺一不可。
**Trade-offs**：只说"谢谢"不够具体，对方不知道什么行为值得重复。

## Pattern: 教练一次一步
**When to use**：用户同时暴露多个 OFNR 问题。
**How**：按 观察→感受→需要→请求 顺序找最先卡住的一步，只练这一步。示范改写，让用户感受差别。
**Trade-offs**：贪多会让用户挫败，反而背离 NVC 的联结目的。
